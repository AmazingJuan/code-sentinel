## Statement of work template


### Title

Code Sentinel

### Abstract

This Statement of Work (SOW) outlines the objectives, scope, deliverables, roles, and timeline for the development and implementation of Code Sentinel, an AppSec Orchestration and Vulnerability Management Platform. The platform centralizes security analysis for software projects by integrating multiple security scanning tools into a single system. Code Sentinel is responsible for orchestrating security scans, receiving and processing reports generated by external security tools, and normalizing their findings into a unified format, which are then stored and made available through a centralized interface. The initial phase of the project focuses on building the core platform and integrating it with Static Application Security Testing (SAST) and Secret Scanning capabilities, with an architecture designed to support additional security analysis tools and vulnerability types in the future.

### Value

The main value of this project lies in centralizing and standardizing the results of multiple security analysis tools that are currently managed independently and reviewed in isolation. By normalizing findings from different scanners into a single format, the platform will reduce the manual effort required to consolidate results, improve the visibility of the security posture of software projects, and provide a consistent, centralized point of reference for security and development teams. The cost should include platform architecture and design, backend and integration development, security tool onboarding (SAST and Secret Scanning), interface development, testing, documentation, and initial post-deployment support.

### Scope

The project involves the development of a web-based platform that allows users to register and configure software projects, execute and orchestrate security scans, integrate external security tools, normalize and store their results, and consult findings through a centralized interface. The system will be intended for AppSec analysts, developers, and platform administrators. It will not include integration with DAST, SCA, IaC or container scanning tools, automated remediation of findings, or native mobile access in this phase.
 
**Scope of Work:**
- User registration and authentication.
- Registration and configuration of software projects.
- Execution and orchestration of security scans.
- Integration with external security scanning tools.
- Support for multiple analysis types on the same platform (SAST, Secret Scanning).
- Processing of the different report formats generated by integrated tools.
- Normalization of findings into a common internal format.
- Storage and historical retention of scan results.
- Centralized interface to view, filter, and review findings.
- Role-based access to platform functionality.
- Extensible architecture to support future security tools and vulnerability types.

**Out of Scope:**
- Integration with DAST (Dynamic Application Security Testing) tools.
- Integration with SCA (Software Composition Analysis) tools.
- Infrastructure as Code (IaC) or container scanning.
- Automated remediation of findings.
- Native mobile application.
- Offline data capture.
- Port scanning and custom in-house scanners (deferred to a later phase, pending confirmation with the client).


### Payment

Payments may be divided according to project milestones to ensure alignment between progress and compensation. A suggested payment schedule is 20% upon contract signing, 25% after requirements analysis and architecture design approval, 25% after completion of the core ingestion, orchestration, and normalization engine, 20% after SAST and Secret Scanning integrations and the centralized interface are completed, and 10% after final testing, deployment, and client acceptance.

## Context


### Present

**Identified Obstacles:**
- Security findings are currently distributed across multiple standalone tools, each with its own format and interface.
- There is no unified view of the security status of software projects.
- Consolidating results across tools requires manual effort and is prone to inconsistency.
- The lack of a normalized format makes it difficult to compare severity and priority across different sources.
- There is no centralized traceability of a finding's lifecycle, from detection to review.

Currently, security analysis results are scattered across different tools, each generating its own reports in its own format. Security and development teams must manually review each tool separately to understand the real security posture of a project, which makes prioritization and reporting slow and inconsistent.


### Future

With the implementation of Code Sentinel, the organization will have a centralized platform to orchestrate security scans and consolidate their results. AppSec analysts and developers will be able to view normalized findings from multiple tools in one place, filter and prioritize them consistently, and track their status over time. As a potential future improvement, the platform is designed to support additional analysis types such as DAST, SCA, IaC, and container scanning, as well as port scanning and custom in-house scanners.



## Planning


### Requirements

The system shall provide the following functional capabilities as part of the Minimum Viable Product (MVP):

### FR-01: User Registration and Authentication
The system shall allow users to register and securely authenticate to access the platform.
 
### FR-02: Project Registration and Configuration
The system shall allow users to register software projects and configure their source location for analysis.
 
### FR-03: Security Scan Execution and Status Management
The system shall allow users to execute security scans on registered projects and track their status (pending, running, completed, failed).
 
### FR-04: Scan History
The system shall retain previously executed scans and allow users to consult their results over time.
 
### FR-05: Security Tool Integration and Orchestration
The system shall allow external security tools to be integrated and orchestrated as part of a scan.
 
### FR-06: SAST Analysis
The system shall integrate Static Application Security Testing capabilities to identify vulnerabilities in source code.
 
### FR-07: Secret Scanning
The system shall analyze project source code to detect exposed secrets, credentials, and API keys.
 
### FR-08: Report Processing and Normalization
The system shall process the different report formats generated by integrated tools and normalize their findings into a common internal format.
 
### FR-09: Finding Registration and Classification
The system shall store, classify, and associate each finding with its scan, source tool, location, and severity when available.
 
### FR-10: Centralized Results Interface
The system shall provide a centralized interface to view, filter, and review findings across scans and tools.
 
### FR-11: Security Overview
The system shall provide an overview of the security findings detected for a project.
 
### FR-12: User and Role Management
The system shall manage users and enforce role-based permissions, ensuring each user can only access the features corresponding to their responsibilities.
 
### FR-13: Web-Based Access
The system shall be deployed as a web application, accessible through a standard web browser.
 
### FR-14: Extensible Security Architecture
The system architecture shall allow additional security tools and vulnerability types to be integrated without requiring a complete redesign of the platform.
 

The project deliverables include:
 
- Web platform for security scan orchestration and results management.
- Project registration and configuration module.
- Scan execution, orchestration, and status-tracking module.
- SAST integration.
- Secret Scanning integration.
- Report processing and normalization engine.
- Centralized findings interface with filtering and security overview.
- User and role management module.
- Technical documentation of the integration architecture.
