# Scoping Questionnaire

**Question 1:**
What is the main problem that teams currently face by not having a centralized security results platform?

**Answer:**
The problem is that they commonly manage it through DefectDojo or through automated processes using Power BI. It is a manual process because the information is extracted and then placed into a Power BI dashboard. It is essentially a manual process.

---

**Question 2:**
Who are the main stakeholders of the project?

**Answer:**
The Product Owners.

---

**Question 3:**
Is there a similar solution currently in use?

**Answer:**
DefectDojo, Mesh, and Oppenheimer.

---

**Question 4:**
Is support required for multiple tools of the same type simultaneously (e.g., multiple SAST tools running in parallel), or only one tool per analysis type?

**Answer:**
Yes, multiple tools of the same type are required.

---

**Question 5:**
Is vulnerability finding lifecycle management required (new, under review, false positive, accepted, remediated, reopened)?

**Answer:**
Yes, it is required because each tool has its own set of rules.

---

**Question 6:**
Is it necessary to assign findings to responsible individuals and track their progress?

**Answer:**
It is always necessary. The tools provide vulnerability results across applications, code, and infrastructure. The purpose of these tools is to ensure that these vulnerabilities are resolved. All findings should be addressed, excluding false positives.

---

**Question 7:**
Should the system support SARIF as a generic ingestion format in addition to proprietary formats?

**Answer:**
It depends on the application. It would be good to have a unified format, but the standard itself is not the main concern. Not all the information generated by these tools is reported.

---

**Question 8:**
What volume of scans/results is expected per day/week?

**Answer:**
Code analysis is performed through a scan for each commit.

---

**Question 9:**
How should severity be mapped across different tools that use different scales?

**Answer:**
It depends on the standard we are dealing with. These tools have a problem differentiating between the severity and the actual risk of vulnerabilities. All of them generate severity levels, but they do not all represent the same level of risk.

---

**Question 10:**
How long should historical results be retained?

**Answer:**
It all depends on the organization's retention policy.

---

**Question 11:**
Is an executive dashboard with security posture metrics required?

**Answer:**
Yes, it is necessary because administrators are the ones who need to understand the information. Therefore, it must be presented in the simplest, most concise, and clearest way possible.

---

**Question 12:**
How will the success of the project be measured?

**Answer:**
It can be measured in two ways: by evaluating how well teams understand the collected information and assign the appropriate priority to it, and by evaluating the effectiveness of the remediation processes.
